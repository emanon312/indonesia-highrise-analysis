# 印尼高层建筑数据分析系统 — 技术方案文档

> **用途**：本文档供 Agent 参考，描述从数据采集到 AI 分析的完整技术方案，目标是统计印尼主要城市高层建筑存量，服务于投资决策。
> **当前阶段**：以雅加达（Jakarta）为试点城市，跑通全流程后推广至泗水、万隆等城市。

---

## 一、项目背景与目标

### 核心需求

统计印尼大城市的高层建筑（写字楼、高层公寓等）数量与分布，结合 AI 分析手段，为项目投资提供数据支撑。

### 交付目标

- 各城市高层建筑总量（按类型分类）
- 地理分布热力图与行政区统计
- 重点商务区详细数据（如雅加达的 SCBD、Sudirman、Thamrin 走廊）
- 数据质量评估报告
- 投资视角洞察与建议

### 高层建筑定义

| 级别 | 楼层数 | 说明 |
|------|--------|------|
| 准高层 | ≥8层 | 含部分商业楼 |
| 标准高层 | ≥10层 | **默认分析阈值** |
| 超高层 | ≥15层 | 用于精细化分析 |

## 四、数据获取层详解

### 4.1 路径 A：OpenStreetMap（主力数据源）

**选择理由**：免费、覆盖全球、印尼数据相对完整、可批量查询

**工具**：Overpass API（`https://overpass-api.de/api/interpreter`）

**核心查询语句**（雅加达 ≥10 层高层建筑）：

```overpass
[out:json][timeout:60];
(
  way["building"]["building:levels"~"^(1[0-9]|[2-9][0-9]|[1-9][0-9]{2,})$"]
     (-6.37, 106.65, -6.07, 106.97);
  relation["building"]["building:levels"~"^(1[0-9]|[2-9][0-9]|[1-9][0-9]{2,})$"]
     (-6.37, 106.65, -6.07, 106.97);
);
out body;
>;
out skel qt;
```

**关键 OSM 标签说明**：

| 标签 | 含义 | 典型值 |
|------|------|--------|
| `building` | 建筑类型 | office / apartments / hotel / commercial / mixed_use |
| `building:levels` | 地上楼层数 | 整数，如 "20" |
| `building:use` | 建筑用途（补充） | residential / commercial |
| `name` | 建筑名称 | 用于识别知名地标 |
| `height` | 建筑高度（米） | 部分有，可交叉验证 |
| `start_date` | 竣工年份 | 用于趋势分析 |

**数据局限性**（重要）：
- 印尼 OSM 楼层数据标注率约 30-50%，大量建筑缺失 `building:levels`
- 建议同时抓取所有 `building=office/apartments/hotel` 的要素，不限楼层，再结合高度/体量估算
- 部分老旧建筑数据更新滞后

### 4.2 路径 B：卫星影像 + 计算机视觉（补充验证）

**工具选项**：

| 工具 | 费用 | 适用场景 |
|------|------|----------|
| Google Earth Engine | 免费（注册申请）| 大范围影像分析 |
| Sentinel-2（ESA）| 完全免费 | 10m 分辨率，识别建筑轮廓 |
| Planet Labs | 付费 | 3m 分辨率，细节更好 |
| Mapbox Satellite | 付费/有免费额度 | 快速集成 |

**高度估算方法（阴影法）**：
```
建筑高度 ≈ 阴影长度 × tan(太阳高度角)
太阳高度角可由拍摄时间和地理坐标计算
误差范围约 ±15%，适合做粗略筛选
```

**建筑识别模型选项**：
- `Segment Anything Model (SAM)`：Meta 开源，建筑轮廓分割
- `BuildingNet`：专门针对 3D 建筑识别
- `roboflow` 平台上有预训练的建筑检测模型

### 4.3 路径 C：商业数据库（标杆验证）

| 数据源 | 内容 | 获取方式 |
|--------|------|----------|
| CTBUH（世界高层建筑学会）| 100m+ 超高层完整数据 | 官网免费查询，批量需订阅 |
| Emporis（已关闭，历史存档）| 曾覆盖中高层 | Internet Archive 可抓取 |
| BPS（印尼统计局）| 建筑许可证数据 | `bps.go.id` 部分公开 |
| BPJS Ketenagakerjaan | 企业登记（间接推断写字楼）| 需申请 |
| JLL / CBRE 印尼报告 | 高质量商业地产数据 | 付费研究报告 |

## 五、数据处理层

### 5.1 处理流程

```python
# 伪代码示意（实际用 Python + geopandas）

# Step 1: 读取 OSM GeoJSON
buildings = gpd.read_file("jakarta_buildings.geojson")

# Step 2: 过滤高层（有楼层数据的直接过滤）
highrise = buildings[buildings['building:levels'].astype(float) >= 10]

# Step 3: 无楼层数据的建筑，用面积+已知建筑推算
# 建筑占地面积 > 1000㎡ 且 building=office 的大概率是高层
candidates = buildings[
    (buildings['building'].isin(['office','apartments','hotel'])) &
    (buildings.geometry.area > 1000)  # 投影坐标系下的㎡
]

# Step 4: 空间关联行政区
admin = gpd.read_file("jakarta_admin_districts.geojson")
buildings_with_district = gpd.sjoin(highrise, admin, how='left', predicate='within')

# Step 5: 统计
summary = buildings_with_district.groupby(['district', 'building']).size()
```

### 5.2 建筑类型映射

```
OSM building 标签 → 分析类别

office                → 写字楼
commercial + ≥10F    → 写字楼（推断）
apartments            → 高层公寓
residential + ≥10F   → 高层公寓（推断）
hotel                 → 酒店
mixed_use             → 综合体
retail + ≥10F         → 综合体（推断）
```

### 5.3 数据质量评分体系

| 指标 | 计算方式 | 权重 |
|------|----------|------|
| 覆盖率 | OSM建筑数 / 遥感估算建筑数 | 30% |
| 准确性 | 抽样人工验证的准确率 | 30% |
| 楼层完整度 | 有 building:levels 的比例 | 25% |
| 类型标注率 | 有 building 类型标签的比例 | 15% |

## 六、AI 分析层

### 6.1 建筑分类（LLM 辅助）

对于标签不明确的建筑，用以下 Prompt 让 LLM 辅助判断：

```
你是一个印尼城市建筑分析专家。根据以下建筑信息判断其类型：
- 建筑名称：{name}
- OSM 标签：{tags}
- 地址：{address}
- 占地面积：{area}㎡
- 所在区域：{district}

请判断该建筑属于：写字楼 / 高层公寓 / 酒店 / 综合体 / 其他
并给出置信度（高/中/低）和判断依据。
```

### 6.2 空间聚类分析

使用 DBSCAN 或 K-Means 识别高层建筑聚集区：

```python
from sklearn.cluster import DBSCAN
import numpy as np

# 提取坐标
coords = np.array([[b.geometry.centroid.x, b.geometry.centroid.y] 
                   for b in highrise.itertuples()])

# DBSCAN: eps=0.005 约等于500m，min_samples=5
clustering = DBSCAN(eps=0.005, min_samples=5).fit(coords)
highrise['cluster'] = clustering.labels_

# 密度最高的 cluster 即为 CBD 区域
```

### 6.3 竣工年份趋势分析

从 `start_date` 标签提取竣工年份，绘制历年新增高层建筑数量趋势，判断：
- 存量峰值年份（城市高速发展期）
- 近 5 年新增速度（当前市场热度）
- 在建项目数量（未来供应压力）

### 6.4 投资视角分析框架

对每个区域输出以下维度评估：

```
┌─────────────────────────────────────────┐
│ 区域投资评估卡片                         │
├─────────────────────────────────────────┤
│ 写字楼密度     ████████░░  80%          │
│ 公寓供应量     ██████░░░░  60%          │
│ 新增建设速度   ████░░░░░░  40%          │
│ 基础设施配套   ███████░░░  70%          │
│ 综合投资潜力   ██████░░░░  65%          │
```

## 十、数据质量预期与风险

### 预期数据质量（雅加达）

| 指标 | 预期值 | 说明 |
|------|--------|------|
| OSM 高层建筑覆盖率 | 60-75% | 雅加达 OSM 社区活跃度中等 |
| 楼层信息完整度 | 30-50% | 印尼整体标注率偏低 |
| 类型标注率 | 50-65% | 商业建筑标注率高于住宅 |
| 坐标精度 | >95% | 主要建筑定位准确 |

### 主要风险

1. **楼层数据缺失**：大量建筑无 `building:levels` → 对策：用面积+类型+高度做多因子推断
2. **新建筑未录入 OSM**：竣工 <3 年的建筑可能缺失 → 对策：结合卫星影像补充
3. **住宅公寓被标为 residential**：导致统计偏低 → 对策：加入面积过滤，大面积 residential 视为高层公寓
4. **综合体切割问题**：一栋楼有多个 OSM 记录 → 对策：空间去重（100m 范围内相同类型合并）
